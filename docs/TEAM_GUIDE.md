# 팀 작업 안내

이 문서는 제안서에서 아직 사람마다 남은 일을 적는다. 딥러닝 배포나 C++ 엔진을 처음 해도 읽을 수 있게 썼다.

프로젝트를 한 문장으로 말하면 이렇다. SAR 사진으로 차량 종류 10개를 맞히는 작은 신경망을, 소수점 없는 8비트 정수로 돌려 보고, 그 계산을 C++로 직접 짜서 파이썬과 같은 답이 나오는지 확인한다.

## 먼저 알 단어

| 말 | 뜻 |
|----|----|
| FP32 | 보통의 소수점 학습·추론. 기준 정확도다. |
| INT8 | 값을 -128에서 127 사이 정수로 줄이는 것. 용량과 계산이 줄어든다. |
| 가중치 | 학습으로 고정된 필터 숫자. 사진이 바뀌어도 그대로다. |
| 활성 | 레이어를 지나며 생기는 중간 그림. 사진마다 달라진다. |
| PTQ | 학습이 끝난 뒤에 정수로 바꾸는 것. 다시 학습하지 않는다. |
| QAT | 정수로 바꾸는 과정을 넣어서 조금 더 학습하는 것. |
| bit-exact | 같은 입력에 대해 두 프로그램의 출력 숫자가 한 비트도 다르지 않은 것. |

테스트 정확도는 15도에서 찍은 사진 2425장 중 맞힌 비율이다. 지금 기준점은 **98.64%**(2392/2425)다.

## 이미 끝난 것 (무열)

양자화 실험은 끝났다. ViT는 하지 않는다.

| 방법 | 테스트 정확도 |
|------|----------------|
| FP32 | 98.64% |
| PTQ, 가중치만, 채널마다 스케일 | 98.64% |
| PTQ, 가중치만, 스케일 하나 | 98.60% |
| QAT, 가중치만 | 98.72% |
| PTQ, 가중치+활성, 채널별 99.9% 지점 | **98.72%** |
| PTQ, 활성 스케일을 최댓값으로 잡음 | 47.75% (쓰지 말 것) |

마지막 줄이 낮은 이유는 정수 자체가 나빠서가 아니다. 크기 채널에 아주 큰 점이 몇 개 있어서, 그 최댓값으로 눈금을 만들면 나머지 픽셀이 전부 0이 된다. 채널마다 99.9% 지점으로 눈금을 자르면 98.72%가 나온다.

재현 명령:

```bash
python scripts/recover_full_int8.py
```

결과 표는 `runs/rq1/RQ1_TABLE.md`에 있다.

## 깃허브로 뭘 주고, 뭘 주지 않나

자세한 절차는 `docs/SHARING.md`를 본다. 코드·`artifacts/`·문서는 깃허브로 준다. 이 폴더는 아직 git 저장소가 아니므로, 올리기 전에 저장소를 만들어야 한다.

올리면 안 되는 것:

- `.conda/`, `.venv/` : 파이썬 환경. 용량이 수 GB이고 컴퓨터마다 다시 만들면 된다.
- `data/`, `processed/` : 원본과 전처리 결과. `processed/aconvnet_patches_chen`만 약 9GB다. 깃허브 파일 제한을 넘는다.
- `runs/quant_chen/int8_package/manifest.json` 안의 활성 스케일 : 예전에 실패한 최댓값 스케일이다. 숫자가 여기 있어도 사용하지 않는다.

같이 써야 하는 결과 파일은 `runs/` 안에 있고 합쳐서 약 30MB다. 깃이 무시하고 있으므로, 저장소를 만들 때 이 폴더만 예외로 넣거나 압축해서 따로 전달한다. 팀원이 이 서버를 그대로 쓰면 경로 `/home/asdl/DL_project`를 공유하면 된다.

환경이 없을 때:

```bash
conda activate /home/asdl/DL_project/.conda
```

GPU는 이 서버의 RTX 5060 Ti다. 학습과 평가는 `device=cuda`로 하면 된다.

## 성우가 할 일

C++로 추론 프로그램을 완성하고, 파이썬 정수 계산과 답이 같은지 확인하고, 속도와 메모리 사용량을 재는 것이다. 모델을 다시 학습하지 않는다.

### 받아갈 파일

| 파일 | 내용 |
|------|------|
| `artifacts/int8_package/conv1` … `conv5` | 정수 가중치 `weight_q.npy`, 가중치 눈금 `scale_w.npy`, 소수점 바이어스 `bias_fp.npy` |
| `artifacts/act_scales/full_int8_p999_ch.pt` | 활성 눈금. 입력 2개, 그다음 16, 32, 64, 128개 |
| `docs/ROUNDING.md` | 반올림 규칙 |
| `engine/` | 이미 돌아가는 C++ 초안 |
| `quantize/int_ref.py` | 파이썬 쪽 정답 계산 |

`int8_package/manifest.json`의 `act_scales`는 최댓값 눈금이라 정확도가 무너진다. 활성 눈금은 반드시 `best_ptq_scales.pt`를 쓴다.

### 계산 규칙

1. 정수는 `round(값 / 눈금)` 후 -128에서 127로 자른다.
2. 반올림은 반올림 후 짝수로 붙인다. `numpy.round`, `nearbyintf`와 같다. 0.5를 항상 올리는 방식이 아니다.
3. 가중치만 정수로 두는 경로는 중간 그림을 소수점으로 둔다. 이 경로는 이미 파이썬과 거의 같다.
4. 활성까지 정수로 두는 경로는 채널마다 눈금이 다르다. 출력 채널 하나의 곱으로 끝낼 수 없다. 입력 채널 `c`의 눈금이 곱 안에 따로 들어간다.

```text
결과 = 합(입력정수[c] * 가중치정수[출력, c] * 입력눈금[c] * 가중치눈금[출력]) + 바이어스
```

지금 `engine/`의 full INT8은 입력 눈금이 하나라고 가정한다. 그 가정을 `best_ptq_scales.pt`의 채널별 눈금으로 바꾸는 것이 첫 수정이다.

### 순서

1. `bash engine/build.sh`로 빌드한다. cmake는 필요 없고 g++이면 된다.
2. 가중치만 정수인 경로가 파이썬과 같은 종류를 고르는지 확인한다.

```bash
python scripts/verify_cpp_engine.py --max-samples 32
```

3. 활성 눈금을 채널별로 바꾼 뒤, 같은 입력에 대해 C++ 출력과 `quantize/int_ref.py` 출력을 비교한다. 목표 숫자는 로짓이 완전히 같은 샘플 비율이다.
4. 테스트 2425장에서 C++ 정확도를 잰다. 기대값은 약 98.72%다. 47%대가 나오면 낡은 최댓값 눈금을 쓰고 있는 것이다.
5. 사진 한 장씩 넣을 때 평균 시간과 가장 느린 시간, 모델 파일 크기, 최대 메모리를 잰다. 비교 대상은 같은 CPU에서 돌린 파이토치 FP32다. GPU 숫자는 참고만 한다.

끝나면 표 하나로 정리한다. 정확도, 파이썬과 값이 같은 비율, 시간, 메모리, 파일 크기.

### 하지 않아도 되는 것

SIMD, 실제 보드 이식, ViT. 일정이 밀리면 제안서대로 빼도 된다.

## 현석이 할 일

데이터가 정직하게 나뉘었을 때도 정확도가 유지되는지 보여주는 것이다. 양자화 코드는 수정하지 않는다.

공식 실험은 이미 되어 있다. 17도 사진으로 학습하고 15도 사진으로 시험해 98.64%다. 가중치는 `artifacts/checkpoints/fp32_chen_seed12321.pt`, 데이터는 `processed/aconvnet_patches_chen`이다. 입력은 크기와 위상 두 채널이고, 시험 때는 가운데 88×88을 자른다.

제안서가 의심하는 함정은 두 가지다.

1. **각도가 새는 분할.** 비슷한 각도 사진을 학습과 시험에 반씩 넣으면, 모델이 각도를 외워서 정확도가 실제보다 높게 나온다.
2. **사진 크기로 종류를 맞히는 것.** 종류마다 원본 사진 크기가 다르면, 차량이 아니라 크기를 보고 맞힐 수 있다. 지금 공식 실험은 모두 88×88로 잘라서 이 단서를 없앤 상태다.

만들 표는 이렇다.

| 학습/시험 나누기 | 입력을 88로 자름 | 테스트 정확도 |
|------------------|------------------|---------------|
| 공식 17도 / 15도 | 예 | 98.64% (이미 있음) |
| 사진을 무작위로 나눔 | 예 | 직접 측정 |
| 파일 순서가 붙어 있는 덩어리로 나눔 | 예 | 직접 측정 |
| 공식 분할 | 아니오 (원래 칩 크기) | 가능하면 측정 |

학습 명령의 뼈대는 이렇다. 나누기만 바꾼 데이터 폴더를 `--data-dir`로 지정한다.

```bash
python scripts/train_baseline.py --chen-repro \
  --data-dir processed/aconvnet_patches_chen \
  --out-dir runs/baseline_chen_soc \
  --device cuda
```

무작위 분할과 덩어리 분할용 폴더는 아직 없다. 공식 폴더를 복사해서 학습 사진과 시험 사진의 소속만 바꾼 뒤 같은 명령으로 다시 학습하면 된다. 시드는 12321로 맞춘다. 정확도가 공식 분할보다 크게 높으면, 각도가 새서 부풀었다고 적으면 된다.

칩 크기 실험은 자르기 전의 원본을 쓴다. 전처리 스크립트는 `scripts/preprocess_mstar.py`와 `scripts/preprocess_aconvnet.py`다. 시간이 없으면 88 크롭 실험만 해도 제안서의 핵심은 답할 수 있다. 그 경우 크기 단서 실험은 하지 못했다고 보고서에 한 줄 남긴다.

## 서로 건드리지 않을 것

- 성우는 `quantize/`의 학습 코드를 고치지 않는다. 눈금 파일과 `docs/ROUNDING.md`를 기준으로 엔진만 맞춘다.
- 현석은 `engine/`과 `quantize/`를 고치지 않는다. 데이터 나누기와 정확도 표만 만든다.
- 무열의 정확도 표 숫자(98.64%, 98.72%, 47.75%)는 위 표가 기준이다. 다른 폴더의 예전 실험으로 덮어쓰지 않는다.
